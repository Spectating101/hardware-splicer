# Radxa CM5 official reference PCB contact-to-net comparison

**HS experiment — 2026-11-07.** This is a real source comparison and a native KiCad pad/net inspection fixture, **NOT a connected schematic, validated carrier, or build approval**.

Manufacturer reference carrier PCB: [Radxa CM5 IO board PADS ASCII v2200](https://github.com/radxa/radxa-som-projects/blob/cf5a4b1984fb4321233d2439320bcaea05af4817/cm5/radxa-cm5-io-board/radxa_cm5_io_board_v2200.asc), SHA256 `b229b4c5960aad6376e60258b5a5cd62ea7c8e3f31fde94066ef850fb0e3eeed`. **The module V2.21 and carrier v2200 are not assumed to be exactly the same revision.**
3. Corrected 300-contact CM5 KiCad symbol and 300-pad footprint in PR #300, with community MIT notice retained.

## Results from published routed-endpoint sections

| Inspection | Observed |
|---|---:|
| Numbered compute-module contacts | 300 |
| Contacts appearing in a PCB route endpoint pair | 241 |
| Net names assigned to those 241 contacts | 159 |
| Exact matches between official contact name and PCB net name | 235 |
| Labels differing from source routings | 6 |
| Same physical contact wrongly assigned to two different routed nets | 0 |
| Contacts **not** observable via routed endpoint pairs | 59 |
| Manufacturer contact labeled NC but routed on reference PCB | **1, contact 290** |

For the 200-contact `U33` footprint, **pads numbered over 200 are special mounting/ground tabs**, not the third connector. The separate 100-contact `J24` footprint uses numbers 1–100, mapped to CM5 contacts **201–300**. Without this disambiguation, a naive parser falsely flags contacts 203 and 204 as shorted to ground. The correct source route mapping instead finds contact 203 `TYPEC0_SBU1` and 204 `GPIO3_C0`.

### Exact six different labels

| Contact | V2.21 official label | v2200 reference PCB routed net | Assessment |
|---|---|---|---|
| 106 | `5V_HDMI` | `N17122158` | Named reference rail not proven; power direction needs schematic review |
| 145 | `HDMI0_TX_SBDP` | `HDMI0_TX_SBDP_C` | Possibly board-side segment/series element; not proven equivalent |
| 147 | `HDMI0_TX_SBDN` | `HDMI0_TX_SBDN_C` | Similar candidate reference alias; cannot treat as transparent |
| 153 | `HDMI_TX0_HPD` | `HDMI_TX0_HPD_M0` | Signal mux or net-label distinction to review |
| **290** | **`NC`** | **`RTC_32K_SOC`** | **Potential revision-dependent electrical incompatibility; block direct fabrication** |
| 292 | `VCC_3V3_S3` | `N16884567` | Rail identity and regulation need schematic review |

A pin-label match alone does **not** demonstrate voltage safety, net completeness or route adequacy; equally, a label mismatch can reflect an intentional intermediate net. Investigate source schematics before assigning risk severity.

## Native KiCad result

`REFERENCE_NET_LABELS_ONLY_NOT_ROUTED.kicad_pcb` was generated by KiCad 9 `pcbnew`, with **241 pad-net assignments** across 159 net names and **zero copper tracks**. KiCad 9 re-imported it and preserved all 241 assignments exactly. `kicad-cli pcb drc` reported **0 geometry violations and 82 unconnected items**. The 82 expected failures demonstrate that this is not a routed or electrically complete board, even though it is a valid KiCad file.

Do **not** send this fixture to a PCB manufacturer.

## Reproducible source checks

```bash
curl -fLsS --retry 3 \
  https://raw.githubusercontent.com/radxa/radxa-som-projects/cf5a4b1984fb4321233d2439320bcaea05af4817/cm5/radxa-cm5-io-board/radxa_cm5_io_board_v2200.asc \
  -o /tmp/radxa_cm5_io_v2200.asc

PYTHONPATH=src python3 -m hardware_splicer.cm5_reference_board_netmap \
  --board-asc /tmp/radxa_cm5_io_v2200.asc \
  --vendor-pin-manifest examples/cyberdeck/compute_carrier/cm5_reference/vendor_pin_names.json \
  --output /tmp/cm5_reference_routed_net_map.json

python3 scripts/hs_cm5_reference_net_overlay.py \
  --fixture examples/cyberdeck/compute_carrier/cm5_reference/FOOTPRINT_ONLY_NOT_CONNECTED.kicad_pcb \
  --map /tmp/cm5_reference_routed_net_map.json \
  --output /tmp/cm5_reference_net_inspection.kicad_pcb
```

The audit checks the exact source SHA256, source connector IDs, per-connector numbering and expected manufacturer discrepancies. It **fails closed on changed reference layouts** rather than silently treating unfamiliar contacts as safe.
