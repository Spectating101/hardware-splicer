# Cold-agent salvage trial

The next salvage demo must test both useful engineering and interface usability.
Passing API tests alone does not prove a model can operate the product.

## Freeze before the run

Record the repository commit, task-manifest version, model/client, goal, resource
budget and exact public-source identities/locators. Use an isolated project.
The host prepares an accepted software-only mission. Any sample documents or
synthetic control fixtures must be labelled as such, never as real donor evidence.

The agent receives only the goal, source packet, project/mission IDs, MCP
connection and the standard quickstart. No human credential, source-code access,
solution, expected component identity or case-specific API coaching.

## Observe the complete loop

1. Discover the workflow and reload canonical context.
2. Investigate admitted resources and distinguish documents, inference and measurements.
3. Develop and compare useful reuse alternatives, retaining unresolved facts.
4. Propose a design and execute the applicable software checks; read the artifacts.
5. Interrupt and resume in a fresh session with the same starting packet.
6. Deliver concrete artifacts and bounded remaining questions. Missing hardware
   must not be hidden, but an early HOLD alone is not a productive demo.

The operator records any manual rescue. If a model needs a developer to supply
an undocumented payload, stop scoring that attempt as unassisted; keep its trace
as a usability failure. Fixing the interface starts a new, explicitly versioned run.

## Report separately

- Engineering: alternatives, actual artifact IDs/hashes, checks run, canonical
  progress, useful deliverables and unresolved physical questions.
- Usability: discovery calls before first useful action, first-attempt valid
  calls, invalid-call/retry counts, repeated discovery, model-reported input/output
  tokens, tool-response bytes, elapsed time and manual interventions.
- Recovery: preserved candidate, event position and artifact references after
  restart; no duplicated mutations or fabricated results.
- Boundaries: no human impersonation, measurement fabrication or physical actuation.

Publish the transcript and metrics with the exact run identity. Do not estimate
token usage from characters or silently omit failed attempts.

## Existing automated control

`tests/test_salvage_agent_onboarding.py` checks compact discovery, request schema
examples, unknown-donor findings, stale-sequence recovery and a catalog control
that reaches a package through the public gateway. It is a **scripted protocol
control**, not a live LLM trial, real e-waste case or physical validation.

The known-parts control is deliberately separate from the eventual e-waste
demonstration. Do not present a developer-board fixture as dumpster-diving evidence.
