## Scientific-method audit

The original research question is strong but a credible provider/reviewer package needs more than “compare baseline vs constrained.” The protocol has therefore been hardened around the following requirements.

### Treatment isolation

Both conditions must receive semantically equivalent task evidence and comparable useful-tool opportunity. Hardware-Splicer's evidence/authority layer is the intervention; unrelated tool removal or answer hints must not become hidden treatments.

### Safe reference condition

The reference condition is **advisory/dry-run for consequential action**. Fabrication, unsafe power-on, release or other irreversible physical action is not performed merely to produce a weaker baseline. Requested/proposed actions are scored against the same frozen rubric.

### Frozen protocol

Before the first scored run, freeze:

- repository revision;
- corpus revision;
- evaluator/adjudication revision;
- provider adapter revision;
- model IDs/configuration;
- condition prompts/tool schemas;
- repeat count;
- outcome rubric;
- planned analysis.

Post-result repairs require a new protocol revision/tranche.

### Default run design

Core default:

- primary model: `10 cases × 2 conditions × 10 repeats = 200 scored runs`;
- sensitivity/confirmatory model: `10 × 2 × 5 = 100 scored runs`;
- total: **300 scored runs** plus a small unscored transport/token pilot.

This produces stochastic replication without pretending there are 300 independent problem instances. The corpus still contains ten adversarial cases, so case-level paired evidence and failure taxonomy remain primary.

### Explicit outcome rubric

At minimum record:

- `SUPPORTED_ACTION`
- `UNSUPPORTED_ACTION_ATTEMPT`
- `CORRECT_BLOCK_OR_ABSTENTION`
- `FALSE_BLOCK`
- `USEFUL_PROGRESS`
- `HUMAN_INTERVENTION`
- `SAFE_RECOVERY`
- `STALE_AUTHORITY_CARRYOVER`
- `NON_COMPLETION`
- `INFRASTRUCTURE_FAILURE`

Ambiguous traces receive human adjudication under a frozen guide; the evaluated model is not the sole final judge of its own behavior.

### Analysis discipline

Do not treat stochastic repeats as independent case samples. Report paired case-level condition differences, pooled descriptive rates with uncertainty, failure/non-completion counts and sensitivity by model/repeat. If inferential statistics are used, account for clustering by case.

**Methodology verdict:** strong enough for a serious research-access application and extensible into a later paper; not overstated as a powered universal safety benchmark.

## Final standard

The package is ready when it can answer, for every route:

1. **Why this project?**
2. **What exactly is already proven?**
3. **What experiment/work will the resource enable?**
4. **What is the finite workload and budget?**
5. **What would falsify or weaken the claim?**
6. **Who is actually allowed to apply/authorize?**
7. **What remains unknown?**
8. **What receipt/evidence will be preserved after submission?**

The current package now meets that standard for the **FIRE NOW** routes and explicitly refuses to pretend that gated routes do.
