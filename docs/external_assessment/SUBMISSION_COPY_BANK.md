## 200-word competition summary

Generative AI can produce convincing hardware-engineering answers before the underlying component identity, electrical compatibility, source provenance, revision state or physical behavior is actually known. In hardware, a fluent error can become a fabricated or powered error.

Hardware-Splicer addresses this by separating model reasoning from engineering truth and physical authority. A general-purpose AI agent may reason, propose, revise and operate Hardware-Splicer through MCP/API, while deterministic constraints, provenance-bearing evidence, exact revision/artifact state and explicit human authorization remain independent control layers. The core doctrine is: **AI proposes → deterministic systems constrain → bench evidence decides → human authorizes.**

The current system includes project/revision persistence, source/evidence ingestion, semantic circuit planning, engineering-package generation, physical-evidence records and an authorization ledger. Its canonical MCP gateway exposes 193 backend operations and has been exercised through real stdio and Streamable HTTP clients with stateful project write/read/delete while preserving closed physical authority. A frozen ten-case adversarial SPI-flash corpus tests partial evidence, identity conflict, tool failure, analogy traps and stale revisions.

We explicitly distinguish proven software/MCP infrastructure from pending live-model, fresh physical and independent-operator evidence. The goal is not to claim an infallible AI engineer; it is to make AI-assisted hardware engineering auditable enough that uncertainty cannot silently become physical authority.

## Research abstract — short

**Separating Model Reasoning from Physical Authority in Agentic Hardware Engineering**

General-purpose language models can perform increasingly capable engineering reasoning, but hardware workflows introduce a distinct safety problem: plausible model output can cross into fabrication, power-on or release decisions before component identity, evidence provenance, revision state or physical behavior is established. We present Hardware-Splicer, a model-independent environment that separates semantic agent reasoning from deterministic engineering constraints, provenance-bearing evidence and scoped human authority. The system exposes its canonical engineering backend through MCP while retaining revision/evidence gates outside the model. A frozen ten-case adversarial SPI-flash corpus covers source-order perturbations, partial evidence, component-identity conflict, tool failure, plausible wrong analogy and stale revision. Current evidence establishes the deterministic software/MCP infrastructure and replayable external-agent test harness; live external-model, fresh physical and independent-operator results are reported only when those experiments are executed. The contribution is an auditable experimental architecture for studying whether useful agentic engineering can be increased without allowing model confidence to silently acquire physical authority.

## Product pitch — 30 seconds

AI can already suggest how to build hardware. The dangerous part is deciding when that suggestion is trustworthy enough to fabricate or power. Hardware-Splicer gives any general-purpose AI agent a constrained engineering environment: the model proposes, deterministic systems check identity and constraints, evidence stays tied to exact revisions, and physical authority remains human-scoped. Think of it as the auditable engineering shell between an AI agent and the physical world.

## Problem statement

AI-assisted engineering is moving faster than the mechanisms used to distinguish plausible output from verified physical truth. Existing copilots can accelerate design, but a hardware workflow also needs explicit answers to questions such as: Which exact component is this? Which evidence supports that identity? Is the evidence current for this revision? Did deterministic checks succeed? Has anything actually been measured on real hardware? Who is allowed to authorize the next physical action? Hardware-Splicer treats those questions as first-class system state rather than leaving them inside model prose.

## Innovation statement

The novelty is not merely connecting an LLM to EDA tools. Hardware-Splicer makes the model replaceable and keeps engineering evidence and authority outside the model. Its canonical MCP gateway allows general-purpose agents to operate a broad engineering surface, while exact project/revision state, deterministic constraints, provenance-bearing evidence, explicit real-vs-simulated status and scoped human authorization remain independently enforced. This makes agent behavior replayable and creates a measurable boundary between reasoning quality and physical authority.

## Technical contribution statement

Hardware-Splicer combines: (1) canonical API/MCP access to project and engineering state; (2) deterministic engineering/evidence constraints; (3) explicit unresolved-state propagation; (4) revision/artifact-bound evidence; (5) real-vs-simulated physical-proof discipline; (6) scoped human authorization; and (7) adversarial case/trace replay. The current MCP gateway is generated from the canonical product backend rather than duplicating engineering logic, exposing 193 operations through four generic discovery/dispatch tools.

## Commercial / practical value statement

The initial bounded market is semiconductor test and validation support hardware—adapter boards, carrier boards, fixtures and lab/NPI support hardware—where repeated engineering work is costly but false confidence can also destroy time and equipment. Hardware-Splicer is intended to reduce the cost of agent-assisted engineering without making the model the final authority. Commercial value and platform-reuse economics remain hypotheses until measured with real external cases.

## Safety / trustworthiness statement

Hardware-Splicer does not promise zero hallucination. It instead makes a narrower engineering promise: a model's unsupported or wrong answer should not automatically acquire physical authority. Missing or stale evidence can remain blocking; real evidence must be explicitly distinguished from simulation; and relevant revision/artifact changes can invalidate prior evidence or authorization.

## Current evidence statement

Proven: frozen software architecture, deterministic adversarial evaluation discipline, validated ten-case unseen SPI corpus, real MCP stdio and Streamable HTTP operation, canonical stateful write/read/delete through MCP, 193-operation canonical gateway coverage, and executable external-agent trace/replay infrastructure.

Pending: live external-model execution on the unchanged corpus, fresh SPI revision-bound physical correctness, independent human-operator completion, and demonstrated industrial/platform economics.

Not claimed: universal correctness, autonomous production certification, zero hallucination, qualified-engineer replacement or production readiness.

## Why now

General-purpose agents are becoming capable enough to operate tools rather than merely answer questions. That moves the engineering problem from “Can a model suggest something useful?” toward “What should a tool-using model be permitted to claim and authorize?” Hardware-Splicer provides a concrete hardware domain in which that question can be measured against deterministic state, evidence provenance and physical reality.
