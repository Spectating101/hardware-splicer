## Project name

Hardware-Splicer: A Bounded Engineering Environment for Tool-Using AI Agents

## Short subtitle

Auditable agentic hardware engineering under bounded physical authority

## Category emphasis

Graduate AI Agent Architecture / Smart Manufacturing

## 50-word summary

Hardware-Splicer lets general-purpose AI agents perform bounded hardware-engineering work through MCP while deterministic constraints, provenance-bearing evidence, exact revision state, and scoped human authority remain independently authoritative. The system targets semiconductor test and validation support hardware and is designed so model uncertainty cannot silently become fabrication or power-on authority.

## 100-word summary

Hardware-Splicer is a model-independent environment for bounded AI-assisted hardware engineering. A general-purpose agent can reason, inspect evidence, propose changes, and operate engineering workflows through MCP, while deterministic constraints, provenance-bearing evidence, exact project revisions, physical-proof records, and scoped human authorization remain outside the model. The current system exposes 193 canonical backend operations through its MCP gateway and includes a frozen ten-case adversarial SPI-flash evaluation corpus. Rather than promising an infallible AI engineer, Hardware-Splicer is designed so that unsupported or wrong model output cannot silently acquire fabrication, power-on, or physical-release authority.

## Innovation statement

The innovation is not merely connecting an LLM to engineering tools. Hardware-Splicer makes the model replaceable and keeps engineering truth and physical authority outside it. Exact/unresolved identity, provenance-bearing evidence, deterministic constraints, revision/artifact binding, explicit real-vs-simulated physical evidence, and scoped human authorization remain independently enforced while the agent operates through MCP.

## Application statement

The initial bounded application is semiconductor test and validation support hardware such as adapter boards, carrier boards, validation fixtures, and lab/NPI support hardware. These repeated engineering workflows can benefit from AI acceleration but also impose real physical cost when assumptions are wrong or evidence is stale.

## Technical proof statement

Current exact-head evidence establishes real MCP stdio and Streamable HTTP operation, canonical stateful project write/read/delete, a 193-operation backend surface, a validated frozen ten-case adversarial SPI corpus, and external-agent trace/replay infrastructure. MCP itself does not grant physical authority.

## Limitation statement

The actual live external-model ten-case run, fresh revision-bound SPI physical correctness, independent human-operator completion, industrial economics, and production readiness remain pending and are not claimed.

## One-sentence close

Hardware-Splicer does not need the AI to be infallible; it needs uncertainty to remain unable to silently become physical authority.
