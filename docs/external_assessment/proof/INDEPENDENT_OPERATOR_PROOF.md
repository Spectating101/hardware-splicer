# Independent Operator Proof

**Status: PENDING**

This proof asks whether a technically competent outsider can use the normal Hardware-Splicer surface without repository-specific coaching.

## Operator conditions

The operator should not be a person who already knows the hidden architecture, expected answer or repository internals for the case.

They may receive:

- normal installation/setup instructions;
- normal UI/API/product surface;
- the engineering task;
- hardware/source materials normally available to an engineer.

They should not receive:

- source code as coaching;
- hidden tests;
- golden answers;
- expected evaluator result;
- instructions that reveal fixture-specific semantics.

## Measure and preserve

- operator identity or pseudonymous stable identifier;
- independence attestation;
- task and materials provided;
- start/end time;
- completion state;
- confusion points;
- interventions/help requested;
- incorrect assumptions;
- blocked actions;
- system errors;
- actual engineering result;
- source-code-not-required attestation;
- procedure identifier;
- artifacts and hashes.

## Outer audit

After the attempt, compare:

1. what the embedded operator/model believed;
2. what deterministic systems reported;
3. what the independent user believed/did;
4. what the bench/physical evidence actually showed.

Do not coach the operator during the task merely to improve the completion score. Intervention is itself useful evidence and should be recorded.
