# Overlay — DATE 2027 Late Breaking Results

## Decision

**FIRE-LATER.** Do not rush the September full-paper route. Use the November 29 LBR deadline after the external-proof tranche has had time to generate real results.

## Recommended title

**Late Breaking Results: Evidence-Constrained Agentic Engineering with Revision-Bound Physical Authority**

## Why DATE

Hardware-Splicer sits at the intersection of:

- electronic-system design/test tooling;
- AI-native design automation;
- embedded/cyberphysical engineering;
- verification, safety and dependability;
- model-driven tool use.

The DATE LBR format is particularly appropriate because it accepts novel approaches or sufficiently mature results that indicate viability without requiring a full mature-paper narrative.

## Submission condition

Do not submit a DATE LBR based only on the current MCP infrastructure unless the two-page argument is genuinely novel and evidence-backed enough to stand on its own.

Preferred trigger: at least one of the following exists by November:

1. frozen live external-model ten-case result;
2. fresh revision-bound SPI physical result;
3. independent operator result;
4. controlled cross-model comparison using the same MCP/evidence shell.

The strongest LBR combines (1) with (2).

## Two-page structure

### Page 1

**Problem.** Tool-using AI agents can cross from plausible design suggestions into fabrication/power decisions before engineering truth is established.

**Method.** Hardware-Splicer separates model reasoning, deterministic constraints, revision/evidence state and human physical authority. General-purpose agents operate through MCP against the canonical backend.

**Figure 1.** Agent → MCP → HS → evidence/authority architecture.

**Evaluation.** Frozen ten-case adversarial SPI corpus, outer adjudication and authority-violation metrics.

### Page 2

**Result table.** Actual live-agent / physical results only.

Suggested columns:

- case family;
- completed MCP trajectory;
- unsupported-source violation;
- authority violation;
- unresolved-state behavior;
- outer engineering outcome;
- physical result if applicable.

**Figure 2.** One failure→block→repair→revalidation trace or equivalent-case drift example.

**Limitations.** Bounded hardware domain, small structured corpus, pending industrial economics, no production-readiness claim.

**Contribution.** Demonstrates that agent reasoning quality and physical authority can be measured independently in an EDA-adjacent workflow.

## Claims to avoid

- broad “AI-native EDA replacement” claim;
- universal safe-agent claim;
- production manufacturing readiness;
- physical correctness without fresh measurements;
- using operation count as novelty.
