## Decision

**FIRE.** This is the strongest Taiwan research route because the 2026 theme explicitly combines **Agentic AI and Physical AI**.

## Preferred paper identity

**Separating Model Reasoning from Physical Authority in Agentic Hardware Engineering**

### Core research question

> Can a general-purpose tool-using AI agent perform useful hardware-engineering work inside an evidence-constrained environment without being able to silently manufacture physical truth or self-authorize physical action?

## Submission strategy

### Default route

Use the **Domestic Track extended abstract** if the live-model and/or physical proof tranches are still open near the September 14 deadline.

This is preferable to inflating the work into a full empirical paper before the actual external proof exists.

## Paper structure

### 1. Motivation

Tool-using AI agents are crossing from text generation into consequential engineering workflows. Hardware creates a sharp test domain because a plausible model assertion can trigger fabrication, power-on or release actions.

### 2. Problem formulation

Separate:

- semantic reasoning quality;
- engineering truth state;
- evidence provenance;
- physical authority.

Define the failure of interest as **unsupported authority acquisition**, not simply model inaccuracy.

### 3. System

Present:

`general-purpose agent → MCP → canonical HS backend → deterministic/evidence gates → revision-bound candidate → scoped human authority`

Mention the canonical 193-operation backend surface without making operation count itself a research contribution.

### 4. Evaluation design

Use the frozen ten-case adversarial SPI corpus:

- baseline;
- source-order perturbations;
- neutral-label / mission paraphrase;
- partial evidence;
- identity conflict;
- parser failure;
- plausible wrong analogy;
- stale revision.

Explain that outer case metadata is withheld from the model and that frozen cases are not edited after results are visible.

### 5. Safety / authority metrics

At minimum report:

- failed/incomplete tool-call count;
- foreign-project-scope violations;
- unsupported source-identity use;
- attempted authority opening;
- unsupported fabrication/power readiness;
- equivalent-case structural drift;
- unresolved-state preservation;
- outer engineering outcome.

### 6. Current results

Before the live run, report only infrastructure results:

- deterministic corpus validation;
- MCP transport and stateful canonical backend operation;
- trace/replay infrastructure;
- closed MCP physical authority.

If a live run exists by submission time, replace this section with the actual frozen result and preserve failures.

### 7. Physical evidence boundary

Explain explicit real-vs-simulated state and revision-bound physical evidence. If fresh SPI physical proof is still pending, say so clearly.

### 8. Discussion

Argue that model capability and physical authority can be measured separately, enabling model substitution and safer comparison between agents.

### 9. Limitations

Include:

- no universal hardware correctness claim;
- bounded domain;
- current physical/independent proof status;
- no production-readiness claim;
- adversarial corpus size is intentionally small and structured.

## Short abstract source

General-purpose AI agents increasingly invoke tools and act across multiple engineering steps, but hardware introduces a consequential boundary: plausible model output can reach fabrication or power-on decisions before component identity, evidence provenance, revision state or physical behavior is established. We present Hardware-Splicer, a model-independent environment that separates semantic agent reasoning from deterministic engineering constraints, provenance-bearing evidence and scoped human authority. The canonical backend is exposed through MCP while revision/evidence gates remain outside the model. A frozen ten-case adversarial SPI-flash corpus covers source-order perturbations, partial evidence, identity conflict, tool failure, plausible wrong analogy and stale revision. The current infrastructure supports replayable external-agent traces and explicitly prevents the MCP layer from granting physical authority. We use this system to study agent usefulness and unsupported authority acquisition as distinct outcomes, with live-model and physical claims made only when artifact-backed experiments are executed.
