# Function → technology → manufacturer component candidate → native clearance verification

Date: 2026-10-31. Stacked on PR #237 (technology option screening) and PR #236 (function-first MachineProject).

## Scope, and why this is not a functioning filter

The previous stage ranked a passive sediment depth-media cartridge as the simplest **study hypothesis** for a controlled non-potable particle challenge. Here we identify a real published product pair for **component-envelope and suitability research only**, connect it to the exact source functional specification and selected study mechanism, and use native OpenSCAD to test dimensional reproducibility. None of this verifies filtration efficacy, an assembled fluid path, pressure behavior, microbial or drinking-water safety, or an authorized physical build.

Both are 10-inch nominal product-family formats; the **actual internal clearance and seal-seat compatibility remain unverified**. It is *not appropriate* to assert fit merely because cartridge diameter (60.5 mm) is less than **external** housing diameter (118 mm). We do not generate an internal cartridge seat. Product identity and source documents are manually transcribed; PDFs are **not archived or cryptographically snapshotted** by this workflow. This is a documentary candidate, not authenticated purchased stock.

## Requirements that remain unresolved

- `REQ_FLOW` target 0.5 L/min is **different** from both manufacturers' pressure-drop data points (5 US gpm = ~18.9 L/min). **No interpolation or pressure-loss projection** is calculated. Source feed pressure, flow losses in tubing, housing/cartridge fouling, and hose/connector ratings must be established before a hydraulic model.
- `REQ_PARTICLE` target ≥70% turbidity reduction has **no measured manufacturer support for the specified lab challenge** in the reviewed tables. Nominal 5 µm does not imply a 70% reduction of turbidity or any contaminant health benefit; independent paired measurements are mandatory.
- `REQ_LEAK`, `REQ_BYPASS`, `REQ_SERVICE`: published housing maximum 125 psi is **not a set operating pressure or verified installation pressure**. Exact seals, hose adapters, venting and selected test pressure remain open; housing shell must be manufacturer-produced/rated, not generated by HS.
- `REQ_MONITOR`: differential-pressure taps/sensors have not been selected or calibrated; water quality cannot be inferred from a ΔP signal.

## Native mechanical result

The component preflight emits `clearance.scad` containing **two independent non-physical solids**:

1. Cylinder **Ø118 × 308 mm** representing a conservative simplified external envelope of housing 158007. This is a bounding primitive, not the manufacturer's detailed geometry.
2. Cylinder **Ø118 × 150 mm**, placed below the housing, representing an **illustrative engineering service corridor**. The 150 mm is a *designer assumption*, not supplied by Pentair or validated for removing the 10-inch cartridge or housing sump.

An independent OpenSCAD CLI renders each solid as STL and `trimesh` checks watertightness, bounding dimensions, winding, and geometry volume. Recorded hashes tie real STL files to the original source specification, the documented technology selection, and the manufacturer-reference candidate. This is a **clearance study**, never a printable filter housing, drill template, threaded component, approved fixture, pressure vessel or mechanical-load test.

## Reproduction

Run in a shell containing the HS Python development environment, native OpenSCAD and `trimesh==4.8.3`:

```sh
python scripts/compile_function_intent_001.py --brief examples/functionality/water_filter_nonpotable_bench_001.json --out /tmp/hs-water-functions
python scripts/compare_function_technologies_001.py --functional-package /tmp/hs-water-functions --options examples/functionality/water_filter_technology_options_001.json --out /tmp/hs-water-options
python scripts/study_filter_components_001.py --functional-package /tmp/hs-water-functions --technology-study /tmp/hs-water-options --components examples/functionality/water_filter_component_candidate_001.json --out /tmp/hs-water-parts
python scripts/verify_filter_clearance_geometry_001.py --project /tmp/hs-water-parts
pytest -q tests/test_filter_component_preflight.py
```

The three GitHub Actions jobs run on the exact same commit, with the third job downloading receipts from the earlier two. On successful execution, the evidence bundle contains:
`COMPONENT_REFERENCE.json`, `COMPONENT_PREFLIGHT.json`, `COMPONENT_BOM.json`, `clearance.scad`, `COMPONENT_PACKAGE_RECEIPT.json`, `clearance_housing.stl`, `clearance_service.stl` and `RENDERED_CLEARANCE_EVIDENCE.json`.

## Engineering and authority decisions

**Documentary component identification:** yes, manufacturer-issued source references for this exact SKU.  
**Fully sourced/qualified BOM:** no; tubing, adapters, pressure instrumentation, cartridge service bracket, media-fouling and actual part revisions are unknown.  
**Actual low-flow hydraulic calculation:** no; insufficient rated operating conditions.  
**Independent actual water-quality test:** no.  
**Native physical engineering output:** only simplified OpenSCAD envelopes for spatial planning.  
**Fabrication, procurement, pressure testing, pump/valve operation, human use, drinking water safety:** **all unauthorized.**

Next engineering gate: reconcile actual selected feed supply, known safe non-potable particle challenge, representative pressure-flow data and vendor approved mounting/fitting accessories, then derive testable detailed assembly CAD and wet/dry instrumentation isolation. The source-backed component selection may change if those findings reject this nominal pair.
