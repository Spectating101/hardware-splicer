# v1.1 interface layer — shipped scope reference

**Status:** Shipped in **`v1.1.0`** (stable historical interface baseline)  
**Predecessor:** [v1.0.2](../RELEASE_NOTES_v1.0.2.md) bring-up proof  
**Current operating state:** [`HARDWARE_SPLICER_OPERATING_STATE.md`](HARDWARE_SPLICER_OPERATING_STATE.md)  
**Current competitive shell candidate:** PR `#104` — Review / Compare / Verify / Bring-up

This document records what v1.1 shipped. It is **not** the current frontend roadmap and must not override the canonical operating state or the competitive frontend closure contract.

---

## Product category

> **Self-hosted auditable hardware bring-up + design verification workbench**

Not a bring-up checklist alone. Not a browser ECAD suite.

---

## What v1.1.0 ships

| Surface | What it proves |
|---------|----------------|
| **Readiness verdict** | Blockers before fab / power-on |
| **Design verify** | KiCanvas → truth → BOM → fab → exports |
| **Wiring** | Topology Mermaid + narrative guide |
| **Interface lab** | Adapter proving ground (canvas, circuit-json, netlist) |
| **Authority layer** | `PROJECT_PACKAGE`, DRC, bench gates |

The current vNext frontend work does not replace those authority semantics; it reorganizes them into a more competitive artifact-first shell.

---

## Out of scope

- Native Windows installer  
- Full tscircuit editor embed  
- Production autoroute as default UX  
- KiCad MCP as hard runtime dependency  
- Public SaaS  

These remain historical v1.1 exclusions. Current scope decisions are governed by `HARDWARE_SPLICER_OPERATING_STATE.*`.
