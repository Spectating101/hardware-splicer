## Confirmed defects and repairs

1. **BH1750 observation integration.** The observation checker only recognized
   BME280's successful reading grammar and only attributed sensor faults to
   BME280. A valid BH1750 scan followed by a read fault still reported consistency.
   The checker now uses the planned sensor descriptor's complete reading grammar,
   preserves faults and recovery, and reports BH1750 boot as presence only. In
   mixed-sensor plans, a common fault is attributed only when the current BOOT
   address identifies its sensor; an unbound fault cannot be assigned to both.
   Seven new regression cases failed on the original code. The HTTP test also
   asserts operator-supplied provenance and no persistent evidence writes.
2. **Benchmark output admission.** The benchmark accepted empty, partial,
   duplicate and unknown scenario output, and crashed on non-object records.
   The core lane also ignored findings. Both lanes now reuse the production
   verifier's strict expected-scenario, boolean-pass, finding and exit contract.
   They also use the existing bounded process-group runner instead of raw
   subprocess capture. New tests exercise invalid output for core, BME280 adapter
   and BH1750 adapter lanes, plus complete valid output controls.
3. **Avoidable runtime-test skip.** The real-vendor runtime test only searched its
   own checkout's cache. It now honors `HS_VENDOR_LIBS`, like the other vendor
   tests, so an isolated checkout can use explicitly provisioned dependencies.
