## Engineering behavior delivered

1. `repair_discrimination.py` now checks **distinct physical component-path signatures** irrespective of load, temperature, time or symptom wording. Same route passing and failing with different operating conditions is a confounded observation: **abstain**.
2. Duplicates of identical failing routes do not become independent physical routes; two failures with no common candidate component are also not assigned a made-up single cause.
3. `repair_path_diagnostics.py` retains the existing transparent cost/reversibility ranking when real contrast exists, and now appends `recommended_tests`: bounded evidence requests, not instructions to automatically power devices or buy parts.
4. `repair_intake.py` permits explicit structured path evidence to be processed **even without prose symptoms**, rather than silently discarding that evidence.
5. `repair_triage_cli.py` exports a machine-readable `REPAIR_TRIAGE.json` and technician-readable `REPAIR_TRIAGE.md` containing candidate hypotheses (if justified), uncertainty, source observation audit, proposed reversible diagnostics, comparison criteria, and **explicitly denied** power/fabrication/repair authority.

### Real generated example (R08)

The checked-in example `benchmarks/repair_corpus_v2_20261023/triage_examples/ps5_load_confounded_REPAIR_TRIAGE.md` was generated by the actual module. It correctly says **NO ranked component** and proposes review of existing operating-condition evidence before touching electrical hardware. It does **not** say “PSU verified bad” or recommend energized PSU inspection.

### Run on your own low-voltage repair observation

Prepare JSON with `repair_intake` containing `device_hint`, `symptoms`, and optional `path_evidence: {components: [{id, label, service_cost_rank, reversible_test_available}], path_tests: [{outcome: pass|fail, path: [component_id, ...], condition: ...}], interventions: [{component_id, outcome: no_change}]}`.

```bash
python -m hardware_splicer.repair_triage_cli example_repair_intake.json ./repair_report
cat repair_report/REPAIR_TRIAGE.md
pytest -q tests/test_repair_discrimination.py tests/test_repair_triage_cli.py
```

The system refuses to infer a diagnosed failed component from a lone symptom. Recommended tests are proposed *observations requiring human/safety review*, not machine-controllable procedures.

## Main remaining blockers

1. The engine still requires a manually declared functional-path graph. Actual source discovery from schematics, measurements, fault logs, known-good donor inventory and photographs remains a major gap.
2. It has no independent test-instrument execution, bench session verification, physical repair, cost quote, or repair signoff.
3. A candidate may be reasonable yet tied by service-cost defaults; it is **not** proof of causality.
4. No genuine commercial AI model baseline could be run within this work, and the existing comparison in PR #206 is only against a simple frequency heuristic. Prepared answer-hidden prompts and audit receipts remain available to run a real external model with authorized access.

**Next gate:** obtain independent source evidence and a new unseen confirmed-fix holdout; run the available commercial/external model on identical evidence and collect authentic transcripts. Improve actual fault localization and economic loss prevention, not cosmetic test counts.
